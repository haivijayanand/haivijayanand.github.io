01The requirement: why DOS had to exist

In 1980 the microcomputer world ran on 8-bit processors (Intel 8080, Zilog Z80) and the dominant operating system was Digital Research's CP/M. Thousands of business programs — WordStar, dBase, SuperCalc — were written for CP/M. Then Intel's 16-bit 8086/8088 arrived, able to address 1 MB of memory instead of 64 KB. Hardware was ready; the 16-bit operating system was not: Digital Research's CP/M-86 was running late.

Two customers felt the gap first. Seattle Computer Products (SCP) was selling an 8086 S-100 board from late 1979 with no operating system to run on it. And in 1980 IBM, in a crash project at Boca Raton ("Project Chess"), set out to build a personal computer in about a year using off-the-shelf parts and outside software — including the operating system.

What the operating system had to do

RequirementWhy it matteredHow DOS answered it
Run on the Intel 8088 (16-bit, 1 MB address space)IBM chose the cheaper 8-bit-bus version of the 8086Written in 8086 assembly; ran in the CPU's only mode then, real mode
Look like CP/MSoftware houses had to port their CP/M programs fastCP/M-style system calls, function numbers, the File Control Block and the A> prompt; translators converted 8080 code to 8086 almost mechanically
Fit in a tiny machineBase IBM PC had 16 KB RAM and single-sided floppiesSmall kernel, loaded from a 160 KB 5.25" floppy
Better disk handling than CP/MCP/M's allocation and directory scheme was slow and limitedThe File Allocation Table (FAT) borrowed from Microsoft's Stand-alone Disk BASIC
Be available now and be cheapIBM had a fixed launch dateMicrosoft licensed an existing OS and adapted it; IBM priced it at US$ 40
Hide hardware details from programsSame software should run on future machinesLayered design: ROM BIOS → DOS kernel → application programming interface INT 21h
The design brief was not "build the best OS". It was "build a CP/M-compatible 16-bit OS, today, small enough for a floppy". Almost every strength and weakness of DOS traces back to that brief.

02Birth: from QDOS to MS-DOS

Tim Paterson at SCP began writing an operating system in April 1980 to sell his company's 8086 board. Internally it was called QDOS — "Quick and Dirty Operating System" — and it was marketed as 86-DOS.

When IBM came to Microsoft (then a languages company selling BASIC) for an OS, Microsoft licensed 86-DOS, hired Paterson, and adapted it for the IBM PC. Just before the PC launched, Microsoft bought the system outright — and crucially kept the right to license it to other manufacturers. IBM sold its copy as PC DOS; Microsoft licensed MS-DOS to every clone maker. When Compaq and others built IBM-compatible PCs, each one needed MS-DOS. That licence is what made Microsoft.

SCP later sued Microsoft, claiming the IBM connection was hidden during the purchase; the case was settled for close to US$ 1 million.

03Technology inside DOS

Layered structure

Application programs Lotus 1-2-3, WordStar, Turbo Pascal…
COMMAND.COM the shell: prompt, internal commands, batch files
MSDOS.SYS (IBMDOS.COM) kernel: files, memory, processes · INT 21h
IO.SYS (IBMBIO.COM) device drivers, boot-time init
ROM BIOS firmware: keyboard, screen, disk · INT 10h/13h/16h
Hardware 8088 CPU, RAM, floppy/hard disk, CGA/MDA

Programs were supposed to call only INT 21h. For speed, many wrote straight to video memory or the hardware ports — which is why "100 % IBM compatible" became the test every clone had to pass.

04The 640 KB problem

The 8088 could address 1 MB. IBM reserved the top 384 KB for video memory and ROM, leaving 640 KB of "conventional memory" for DOS and programs. In 1981 that was enormous; by 1988 spreadsheets and CAD needed far more. A decade of DOS history is the story of working around this wall. Tap a block to read about it.

05Version explorer — each version answered new hardware

Click a version. Blue chips are stand-alone DOS; amber chips are DOS hidden inside Windows 9x.

Pattern to notice: almost every major DOS version was triggered by a new IBM machine or storage medium — XT hard disk (2.0), AT high-density floppy (3.0), PS/2 3.5" disk (3.3), large hard disks (4.0). Only 5.0 and 6.0 were driven by software competition, mainly from DR-DOS.

08Decline and retirement

DOS's weaknesses were built into its brief: single user, single task, no memory protection, 640 KB, 8.3 file names, real mode. The 386 processor (1985) could do protected mode, virtual memory and multitasking — DOS could not use any of it without bolt-ons.

DOS alone→ Windows 3.x on DOS
1990–92→ Windows 95/98/ME
DOS 7–8 hidden as boot loader→ Windows XP (NT kernel)
Oct 2001 — no DOS underneath
  • 1994: MS-DOS 6.22 — last version sold on its own.
  • 1995–2000: DOS 7.0, 7.1 and 8.0 exist only inside Windows 95, 98 and ME, mainly to boot Windows and run old programs.
  • 31 Dec 2001: Microsoft ends support for MS-DOS (with Windows 3.x and Windows 95). The DOS components of Windows 98/ME were supported until July 2006.
  • Windows NT/2000/XP and later: DOS programs run in an emulated "NT Virtual DOS Machine" (NTVDM) — present only in 32-bit Windows, up to 32-bit Windows 10. 64-bit Windows and Windows 11 cannot run DOS programs natively.

10Legacy you still use every day

  • Drive letters — your Windows disk is C: because A: and B: were floppies.
  • Backslash paths — \ because / was already taken for command switches in DOS 1.
  • Reserved names — you still cannot name a Windows file CON, PRN, AUX or NUL.
  • CR+LF line endings in Windows text files (inherited via CP/M).
  • FAT32 / exFAT on every camera card and USB stick.
  • Commands dir, copy, cd, del, ren still work in cmd.exe.

Source code is public. Microsoft gave MS-DOS 1.25 and 2.0 source to the Computer History Museum in 2014, put them on GitHub in 2018, and in April 2024, together with IBM, released MS-DOS 4.00 under the MIT licence.

Still at work. DOS and FreeDOS still run embedded controllers, legacy test-rig PCs, CNC machines and BIOS-flashing tools, because a single-tasking OS gives a program complete, predictable control of the hardware — useful for timing-critical data acquisition.

12Lessons for engineers

  1. "Good enough and available" beats "best but late". CP/M-86 was arguably the better product; it arrived later and cost six times more.
  2. Compatibility is a moat — and a cage. CP/M-likeness brought software quickly; the same backward compatibility chained DOS to real mode for 20 years.
  3. Own the licence, not the hardware. IBM owned the PC design; Microsoft owned the software every clone needed.
  4. Abstractions leak under performance pressure. Programs bypassed INT 21h for speed, which froze the hardware design of the PC.
  5. Successors arrive as layers first. Windows began as a program on DOS before replacing it — a pattern we will see again in this series.
