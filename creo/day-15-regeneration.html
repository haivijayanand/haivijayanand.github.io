Parent/Child, Regeneration Failures and Resolve

Every Creo user meets a failed regeneration. Learn parent/child relationships, the Reference Viewer, suppress, reorder, insert mode — and how to fix failures calmly with Edit References and Edit Definition.

⏱ about 2–3 hours🧪 Lab: Break it and fix it❓ 5-question quiz

1Today's goals

  • Explain parents and children and see them in the Reference Viewer
  • Suppress, resume, reorder and insert features
  • Read a regeneration failure and the Notification Center
  • Fix failures with Undo, Edit References, Edit Definition, Suppress or Delete
  • Know resolve mode vs no-resolve mode
  • Build models that fail less

2Parents, children and failure

A feature's parents are the things it was built on: its sketch plane, sketch references, the edges it rounds, the axis it is coaxial with. Its children are the features built on it. Delete or change a parent and every child must find its references again — or fail.

See themSelect a feature ▸ Tools ▸ Reference Viewer, or right-click ▸ Information ▸ Reference Viewer. Parents left, children right.
Suppress / ResumeTemporarily remove a feature and its children from regeneration. Nothing is lost.
ReorderDrag a feature up or down the tree. Creo will not let a child move above its parent.
Insert modeDrag the green Insert Here arrow up the tree; new features go there. Drag it back to the end when done.
When regeneration fails (Creo 4 and later), the model stays open, the failed feature is flagged in the tree, and the Notification Center explains. With regen_failure_handling resolve_mode Creo stops in a Resolve environment until you fix it. Your options: Undo Changes; Edit References (reroute — pick new references for the missing ones); Edit Definition; Suppress (fix later — but don't forget); Delete.
Fail-safe habits: sketch on datum planes; dimension to datums; round and chamfer late; reference axes and datum planes rather than edges; avoid references to rounds; keep sketches simple.

3Do it in Creo

  1. Build the lab's part: base plate 120 × 80 × 12 on TOP; Ø40 × 30 boss sketched on the plate's top face; Ø20 hole in the boss; R3 round at the boss root; Ø9 hole + 2 × 2 pattern in the plate.
  2. Select the boss ▸ Tools ▸ Reference Viewer. Note parents (plate, its sketch references) and children (hole, round).
  3. Suppress the boss: Creo lists the children and suppresses them too. Resume All.
  4. Edit the boss sketch: delete the circle and sketch a 40 × 40 square instead. Finish. Watch Round 1 fail.
  5. Read the Notification Center. Choose Edit References on Round 1 and pick the four bottom edges of the square boss. Regenerate — fixed.
  6. Drag the Insert Here arrow above the boss and add a 1 mm chamfer to the plate edges. Drag the arrow back to the bottom.
  7. Try to drag the hole above the boss: Creo refuses — a child cannot go above its parent.

4Lab: break it and fix it

Click features to see parents (orange edge) and children (blue edge). Suppress or delete to see what goes with them. Then redraw the boss as a square and choose how to fix the failed round.

5Pro tips and common mistakes

  • Fix the first failure first. Later failures are often just children of the first.
  • "Suppress and fix later" is how parts leave the office with a missing round. Add a note or a tree column (Tree Filters ▸ Suppressed objects) and check before release.
  • Look at the tree column Status and the Notification Center rather than guessing which feature failed.
  • When you inherit a fragile model: use Reference Viewer on the failing feature and reroute it to a datum, not to another edge.
  • Deleting a sketch entity and drawing a new one gives it a new ID — any feature referencing the old edge loses it. Modify geometry instead of redrawing where you can.

6Practice

  1. Open any of your Week 1–2 parts and run Reference Viewer on its round features. Re-reference any that use edges of other rounds.
  2. Model a pump bracket badly on purpose (sketch on faces, dimension to rounded edges). Make three big changes and record what fails. Then rebuild it using datums and repeat — count the failures.
  3. Set regen_failure_handling to resolve_mode for one session and compare.
