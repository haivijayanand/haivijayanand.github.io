MATLAB and numerical computing

Engineering is full of matrices and differential equations: stiffness matrices, vibration modes, control loops, filters. In the 1970s solving them meant writing Fortran and waiting for the mainframe. A professor's teaching tool — an interactive "matrix laboratory" — became MATLAB, the common language of engineering computation, and spawned a family of rivals and free alternatives.

01The requirement: mathematics without writing Fortran

By the 1970s numerical analysts had built reliable Fortran libraries: EISPACK for eigenvalues and LINPACK for linear equations, funded by the US National Science Foundation. But using them meant writing a program, compiling, linking, running a batch job and reading a printout. Cleve Moler, a professor at the University of New Mexico who had worked on both libraries, wanted his students to try matrix ideas interactively. Around 1979 he wrote a small Fortran program, MATLAB ("matrix laboratory"), in which you type A = [1 2; 3 4] and eig(A) and see the answer at once. Copies spread among universities for free.

02From classroom tool to industry standard

1983–84 — MathWorks. Engineer Jack Little saw MATLAB's value for control engineering. With Moler and Steve Bangert he rewrote it in C and founded The MathWorks in California in 1984 (it later moved to Natick, Massachusetts). PC-MATLAB ran on the IBM PC.
1985–1990 — Toolboxes. The Control System and Signal Processing Toolboxes made MATLAB the tool of control and DSP engineers.
1990 — Simulink. First released as SIMULAB, it let engineers draw systems as connected blocks — integrators, gains, transfer functions — and simulate them.
2000 — LAPACK. MATLAB 6 switched to the modern LAPACK library and an integrated desktop with editor and workspace.
2006 → — Twice-yearly releases. Named R2006a, R2006b and so on: "a" in spring, "b" in autumn. Embedded code generation (Embedded Coder) made Simulink the basis of "model-based design" in cars and aircraft.
2016 → — Live scripts and the web. Live Editor notebooks, MATLAB Online, and in R2026a (released spring 2026) AI copilots for MATLAB, Simulink and Polyspace.

03Try it: what x = A\b does

MATLAB's backslash solves linear equations — for example the forces in a frame, or nodal displacements in finite element analysis (Episode 29). Inside, it uses Gaussian elimination with partial pivoting (LU decomposition) from LINPACK/LAPACK. Edit the 3×3 system and step through.

05Try it: integrating a dynamic system

  
A Simulink diagram of a spring–mass–damper is two integrators in a loop. The solver steps time forward. Simple methods (Euler) drift or blow up with large steps; MATLAB's ode45 uses an adaptive Runge–Kutta method. Change the step size and compare with the exact answer.

07Today: licences and choices

  
    
    
  • MATLAB licences are per user or network (concurrent); each toolbox costs extra. Campus-wide licences are common in universities, and a Home licence exists for personal use.
    • 
    
  • Free but closed: MATLAB Online basic access, Mathcad Express, Wolfram Engine for developers.
    • 
    
  • Open source: Octave runs most MATLAB scripts unchanged; Scilab/Xcos covers basic Simulink-style work; Python covers almost everything except Simulink's code generation and certified toolchains.
    • 
    
  • Interoperability: MATLAB can call Python and vice versa; data move via .mat (HDF5-based since v7.3), CSV or HDF5.

09Lessons for engineers

  
    
    
  1. Use proven numerical libraries. Never write your own matrix inverse for real work.
    2. 
    
  2. Watch the condition number. A nearly singular system gives answers that look precise but are not.
    3. 
    
  3. Check the solver step. A simulation that "works" may be the numerical method, not the physics.
    4. 
    
  4. Keep scripts, not screenshots. A script is the record of how a result was obtained.
