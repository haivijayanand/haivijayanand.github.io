dBase, FoxPro and Access: databases on the desk

Before cloud apps and ERP, small businesses ran on database programs built by one clever person with dBase, Clipper or FoxPro — stock registers, billing, payroll, member lists. Then the world moved to SQL servers, and the desktop database quietly retired.

01The requirement: records, not just numbers

Spreadsheets handled numbers, but a business also keeps records: thousands of customers, invoices, spare parts, employees. On paper these were card indexes and registers; on mainframes they were COBOL files maintained by a data-processing department. Small firms had neither the money nor the staff.

In 1978 Wayne Ratliff, a contractor at NASA's Jet Propulsion Laboratory, wrote Vulcan for CP/M, modelled on JPL's mainframe program JPLDIS, to manage his football-pool data. Ashton-Tate bought marketing rights and sold it in 1980 as dBase II — "II" because a version 2 sounded more mature.

03Technology inside

  

    
ElementWhat it was

    
Data file.DBF: header describing fields (C character, N numeric, D date, L logical, M memo) followed by fixed-length records; a deletion flag byte per record (PACK removed them)

    
Navigation modelRecord-at-a-time: USE, GO TOP, SKIP, SEEK, DO WHILE .NOT. EOF() — very different from SQL's set-at-a-time thinking

    
IndexesB-tree index files; FoxPro's compound .CDX and Rushmore technology combined several indexes to answer queries very fast

    
Language"xBase": interpreted in dBase; compiled by Clipper; pseudo-compiled and very fast in FoxPro; object-oriented in Visual FoxPro

    
Multi-userFiles shared over Novell NetWare with record locking (RLOCK()) — fragile when a PC crashed mid-write

    
AccessJet database engine, a single .MDB file holding tables, queries, forms, reports and VBA; SQL and visual query design

  






  
04Version explorer

  
Blue chips: dBase and Clipper. Amber chips: FoxPro and Access (Microsoft).

  

  

  
The turning point was dBase IV (1988): late, slow and buggy. Users and developers moved to the faster compatible products — FoxBASE/FoxPro and Clipper — and Ashton-Tate never recovered. It was bought by Borland in 1991.

06Decline and retirement

  
Three forces ended the desktop database era: networks and the internet (shared data needs a server, not a file on a shared drive), SQL as the universal language, and packaged software (accounting, ERP and later cloud apps) replacing custom-built programs.

  
    
    
  • dBase: Ashton-Tate was bought by Borland in 1991; the brand passed through several owners afterwards and survives only as a niche product.
    • 
    
  • Visual FoxPro: Microsoft announced in March 2007 that 9.0 would be the last version; mainstream support ended January 2010 and extended support on 13 January 2015. It was 32-bit only.
    • 
    
  • Access: still part of Microsoft 365 for Windows, used for departmental tools; Access web apps were withdrawn in 2018.
    •

08Legacy

  
    
    
  • The .DBF format still carries the attribute table of every Esri shapefile used in GIS mapping.
    • 
    
  • Thousands of FoxPro and Clipper applications still run in small firms and offices, kept alive in virtual machines and DOSBox.
    • 
    
  • xBase made millions of non-programmers into application builders — the spirit of today's low-code tools.
    • 
    
  • Rushmore-style index combination influenced query optimisation in later Microsoft products.
    • 
  






  
09Lessons for engineers

  
    
    
  1. A data format can outlive every program that wrote it. Choose formats with long lives.
    2. 
    
  2. Record-at-a-time code does not scale to networks; set-based SQL and transactions do.
    3. 
    
  3. A late, buggy release can sink a market leader when compatible competitors exist.
    4. 
    
  4. Plan the migration before end of support, not after — unsupported data systems become risks.
    5.
