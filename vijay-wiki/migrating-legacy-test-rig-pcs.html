Migrating Legacy Test-Rig and Controller PCs: Inventory, Imaging, Compatibility and Validation

K Vijay Anand · Vijay_Wiki quick-reference article · 24 November 2026
Test rigsMigrationDAQWindows

Many test rigs and machines are run by a PC that is ten or more years old: an unsupported operating system, an ageing disk, special interface cards and software that nobody has the installer for. When that PC fails, the rig stops. A planned migration starts by capturing everything about the old system, then rebuilds and proves the new one before the old one is retired.

Key takeaways

  • Image the old disk first, before any repair attempt; use tools that skip and retry bad sectors.
  • Inventory everything: OS, software versions, drivers, interface cards (PCI vs PCIe), serial ports, licences and dongles, network settings, configuration files.
  • Check compatibility early: 32-bit software and drivers, card support on the new OS, software runtime versions.
  • Options: like-for-like rebuild, upgrade of software versions, or virtualise the application (only when no special hardware cards are needed).
  • Validate channel by channel and test every interlock and trip before the rig runs a real test; keep the old PC (or its image) as rollback.

Scripts (e.g. PowerShell exporting installed programs, devices, network configuration and services to CSV) make the inventory complete and repeatable.

3. Imaging a failing disk

  • Stop using the disk; every boot risks more damage.
  • Connect it as a secondary disk to a working machine or boot a recovery environment.
  • Use a recovery-aware imager (e.g. GNU ddrescue) that copies good areas first and retries bad sectors later, with a map file to resume.
  • Work only on the image copy; keep the original disk untouched.
Imaging time ≈ disk size / sustained read rate (bad areas can add hours) Example: 500 GB at 80 MB/s ≈ 1.8 h

5. Validation and cut-over

  • Compare each channel with a known input (calibrator, reference sensor) on old and new systems.
  • Check sample rates, timing, file formats and naming match what downstream analysis expects.
  • Test every interlock, trip and E-stop path with the rig in a safe state.
  • Run a short supervised test; compare data with a previous test at the same condition.
  • Keep the old PC or its image ready to restore until the new system has run reliably for an agreed period.
