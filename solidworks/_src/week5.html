    What the API is

    Everything you click in SolidWorks is also available to a program through the SolidWorks API. A macro is a small program inside SolidWorks: VBA (.swp, the most common), or VSTA in VB.NET/C#. Bigger tools become add-ins written in C# or VB.NET.

    ObjectWhat it isTypical calls
    SldWorksThe applicationActiveDoc, OpenDoc6, CloseDoc, GetExportFileData
    ModelDoc2Any open documentGetTitle, GetPathName, ForceRebuild3, Save3
    ModelDocExtensionMore document functionsSaveAs (export), CustomPropertyManager, SelectByID2
    PartDoc / AssemblyDoc / DrawingDocType-specific functionsbodies, components, sheets and views
    FeatureManagerCreates featuresextrudes, fillets, holes

    Tools ▸ Macro ▸ Record writes code while you click — a great way to discover call names, though recorded code is long and full of exact pick points. Tools ▸ Macro ▸ New / Edit / Run. The API Help (Help ▸ API Help) lists every call with examples — it is the final authority.

    Safety: a macro can overwrite or close files without asking. Test on a copy of the folder; keep backups; never run macros from unknown sources (they can do anything your Windows account can).

    Do it in SolidWorks

    1. Tools ▸ Macro ▸ Record. Change a dimension, rebuild, stop and save as rec1.swp. Open it with Edit and find your dimension value in the code.
    2. Tools ▸ Macro ▸ New → batch_step.swp. Paste the "Parts → STEP" macro from the lab and change the folder.
    3. Copy five parts into a test folder. In the VBA editor open View ▸ Immediate Window, then run with F5. Read the log lines.
    4. Set STEP options first: System Options ▸ Export ▸ STEP → AP214. The macro uses whatever is set there.
    5. Try the PDF macro on a folder of multi-sheet drawings and confirm every sheet is in the PDF.
    6. Try the custom property macro on an open part; check File ▸ Properties.
    7. Assign a macro to a toolbar button: Tools ▸ Customize ▸ Commands ▸ Macro → New Macro Button.

    Lab: macro generator

    Choose a job, set the folder, and click each line of the generated code to see what it does. The code uses the standard SolidWorks API calls and the constants from the SolidWorks type libraries that new macros reference by default.

    Pro tips and common mistakes

    • Object variable not set — something returned Nothing (no document open, wrong document type, file failed to open). Check before using it.
    • Use Debug.Print and the Immediate window rather than many MsgBox lines.
    • Keep macros in a shared, version-controlled folder and put the standard header block at the top so you know what each one does.
    • Recorded selections (SelectByID2 with coordinates) break on other models — select by name instead.

    Draft fast, check slowly

    AI assistants (Claude and others) are good at the shape of a macro: loops, file handling, error checks, comments. They are less reliable on exact SolidWorks API names, argument order and version differences — they may produce a plausible call that does not exist. Treat AI code like code from a new colleague: useful, reviewed before use.

    Give contextSolidWorks version, VBA or VB.NET, document types, folder layout, what "done" looks like.
    Give constraints"Use only calls from the SolidWorks API Help", "no deletion", "log every file", "stop on first error".
    Ask for checksNull checks after every Open, error codes printed, a dry-run mode that only lists files.
    VerifyLook up every API call in API Help; run on copies; read the log.
    Confidentiality: follow your organisation's rules on AI tools. Never paste classified, export-controlled, customer-confidential or personal data into a tool that is not approved for it. For macros you rarely need real data — use dummy folder names and part names.

    Prompt template

    You are helping me write a SolidWorks VBA macro (.swp) for SolidWorks [2024].
Goal: [export every .SLDPRT in a folder to STEP AP214 in the same folder].
Inputs: folder path in a constant at the top. Files: [parts only].
Rules:
- Use only methods documented in the SolidWorks API Help; name the interface for each call.
- Check every object for Nothing before using it; print errors and warnings codes.
- Never delete or overwrite source files. Close each document after use.
- Add a DRY_RUN constant: when True, only list what would be done.
- Comment each block in plain English.
Finish with a list of API calls used, so I can check each one in API Help.

    Do it in SolidWorks

    1. Write your prompt with the template; ask your approved AI assistant for the macro.
    2. Paste it into a new macro. Turn on Option Explicit and Debug ▸ Compile VBAProject — compile errors catch invented names and missing variables.
    3. Look up every API call it lists in Help ▸ API Help: interface, arguments, return value.
    4. Run with DRY_RUN = True on a copy folder. Read the list.
    5. Run for real on the copy. Open three outputs and check them.
    6. Ask the AI to explain any line you do not understand — then confirm in API Help.
    7. Save the reviewed macro with a header block and a note "reviewed by / date".

    Lab: bug hunt

    An AI-drafted macro with four real problems — including one invented API method. Find them before you check.

    Pro tips and common mistakes

    • Compile first: Method or data member not found usually means an invented or wrong-interface call.
    • Ask for small macros and combine them yourself; long AI programs hide more mistakes.
    • When the AI fixes a bug, re-run the whole test — fixes often break something else.
    • Keep a library of reviewed macros; reuse beats regenerating.

    Rules instead of clicks

    DriveWorksXpress (Tools ▸ Xpress Products ▸ DriveWorksXpress, included with SOLIDWORKS) works in four stages:

    1. Capture dimensions, features (suppress/unsuppress) and custom properties of a part or assembly — give each a clear name.
    2. Form: inputs the user fills (numbers, lists, checkboxes).
    3. Rules: Excel-like formulas linking inputs to captured items, e.g. IF(Load>1000,10,8), and a rule for the new file name.
    4. Run: fill the form → DriveWorksXpress creates new, renamed parts, assemblies and drawings.

    The full products (DriveWorks Solo / Pro) add web forms, quotes and more — Xpress is the free entry point and good for families of brackets, frames, shafts and plates.

    Design Checker

    Tools ▸ Design Checker (SOLIDWORKS Professional and Premium) checks documents against standards you define: dimension fonts and arrow styles, allowed materials, units, fully-defined sketches, required custom properties, hole sizes. Build Checks creates a .swstd file — you can learn it from a "golden" document — and Check Active Document lists failures, with automatic corrections for many of them. The Task Scheduler can run it on whole folders.

    Do it in SolidWorks

    1. Model a bracket plate: width, height, thickness, a linear pattern of holes, corner fillets. Name the dimensions (Day 12).
    2. DriveWorksXpress ▸ Capture: width, thickness, fillet radius, hole diameter, pattern count.
    3. Form: inputs Load (number), Width (number), Material (list Steel/Aluminium).
    4. Rules: write the rules from the lab, plus the file-name rule.
    5. Run three variants; open the new files and check names and sizes.
    6. Design Checker: Build Checks — require properties Description, PartNo, Material; require fully defined sketches. Save company.swstd.
    7. Check one of the generated brackets; fix what fails.

    Lab: rules engine

    A small configurator with DriveWorksXpress-style rules. Change load, width and material, read which rule fired, and watch the bracket and the generated file name change.

    Pro tips and common mistakes

    • Model the master robustly first — configurators expose every weak sketch.
    • Keep rules readable; put engineering logic (sizes from loads) in a calculation you can show a reviewer.
    • Store generated files in a separate output folder — never overwrite the master.
    • Design Checker is only as good as its rules: start with five checks that catch real mistakes.

    Vault thinking

    SOLIDWORKS PDM stores files in a vault on a server; you work in a local cache (a vault view in Windows Explorer). PDM Standard comes with SOLIDWORKS Professional/Premium; PDM Professional adds scale, replication, a web client and more automation.

    ConceptMeaning
    Check outGet write access; others see who has it
    Check inSend changes to the vault → new version (1, 2, 3…)
    WorkflowStates (Work in Progress → Pending Approval → Released) and transitions with permissions
    RevisionA label (A, B, C…) given on release; written into the title block and revision table
    Data cardForm showing file properties; edits write to custom properties
    Where Used / ContainsWhich assemblies use this part; what this assembly references
    Get version / RollbackOpen or restore an older version

    Without PDM, use at least a clear folder structure, Pack and Go for releases and a written revision rule. On the 3DEXPERIENCE platform, the same ideas are called maturity states and revisions.

    Do it in SolidWorks PDM

    1. Log in to the vault view in Windows Explorer; browse to your project folder.
    2. Drag a new part into the vault. Fill the data card (Description, PartNo, Material) and check it in.
    3. Open it in SolidWorks, change a dimension; the PDM task pane shows it is not checked out — check out from there.
    4. Save and check in with a comment. Look at the History tab: version 2.
    5. Change state: Submit for approval. As the approver, Approve → revision A.
    6. Right-click ▸ Where Used to see the assemblies affected by a change.
    7. Make a change request, edit, and release revision B. Compare A and B with Get ▸ version.

    Lab: workflow simulator

    Try the buttons in different orders. The simulator refuses illegal moves just as a PDM workflow would — editing without check-out, submitting a checked-out file, approving nothing.

    Pro tips and common mistakes

    • Check in at the end of every day; a checked-out file on a laptop is invisible to everyone else.
    • Check in assemblies with their parts so references stay consistent.
    • Rename and move files inside the vault (or with SolidWorks Rename) — Windows rename breaks references.
    • Agree the revision scheme before the first release: letters, numbers, prototype stages (P1, P2) then A.

    What a good change record says

    What changedEach item with the old and new value: "BASE THK 20 WAS → 25".
    WhyThe problem or request, with a reference (test report, NCR, customer request).
    What is affectedParts, drawings, assemblies (where-used), tooling, CNC programs, manuals.
    What to do with stockUse as is, rework, scrap, use up first — and from which batch the change applies (effectivity).

    In SolidWorks: Annotation ▸ Tables ▸ Revision Table on the drawing; Add Revision creates a row and can place revision symbols (triangles) next to the changed dimensions. With PDM, the revision letter comes from the workflow.

    Where AI helps

    Give the assistant the facts as a list and ask it to turn them into clear, consistent wording in your format. Do not ask it to "figure out what changed" from screenshots, and never let it fill gaps — tell it to list missing information as questions.

    Formats and what they carry

    Neutral formats carry geometry, not the feature tree. An imported part is a "dumb solid" (an Imported1 feature) that you can still cut, fillet and measure — but not edit by its original dimensions.

    • Export: File ▸ Save As → choose the type; set options in System Options ▸ Export (STEP protocol, units, output as solid/surfaces, coordinate system).
    • Import: File ▸ Open the STEP/IGES/Parasolid; options under System Options ▸ Import.
    • Import Diagnostics (Tools ▸ Evaluate ▸ Import Diagnostics) finds faulty faces and gaps, and can heal them; then Knit surfaces into a solid if needed.
    • FeatureWorks (add-in) — right-click Imported1 ▸ FeatureWorks ▸ Recognize Features: automatic or interactive recognition of extrudes, revolves, holes, fillets, chamfers.
    • 3D Interconnect opens native files from other CAD systems directly and keeps a link: Update when the original changes; Break Link to make it independent.
    • Direct editing of dumb solids: Move Face, Delete Face, Replace Face (Day 26).

    Do it in SolidWorks

    1. Export the pillow block as STEP AP214 and as Parasolid. Open both; compare tree, colours and file size.
    2. Download a supplier STEP of a motor or bearing (any vendor site). Open it; run Import Diagnostics.
    3. If faces are listed as faulty, Attempt to Heal All; check with Tools ▸ Evaluate ▸ Check.
    4. Activate FeatureWorks (Tools ▸ Add-Ins); Recognize Features on a simple imported part; edit a recognised hole.
    5. Export a sheet-metal flat pattern to DXF (Day 21) and open it in eDrawings to check the layers.
    6. Save an STL for 3D printing: Options → resolution Fine; check deviation and angle.

    • Agree the format and units with the supplier; send STEP AP214 by default, Parasolid to Parasolid-based systems.

    • Check mass and a few key dimensions after import — tolerance mismatches can leave tiny gaps.

    Modes and tools

    Mode / toolWhat it does
    ResolvedEverything loaded — full editing
    LightweightLoads a subset of model data; parts resolve on demand
    Large Assembly SettingsSwitches off heavy graphics and options above a component threshold (System Options ▸ Assemblies)
    Large Design ReviewOpens very large assemblies fast for review: measure, section, walk-through, and simple mates with Edit Assembly
    Detailing modeOpens a drawing without loading the models, for annotations
    SpeedPakA configuration of a sub-assembly that keeps only selected faces/bodies — light in the parent
    DefeatureMakes a simplified, IP-safe part or configuration (remove internal detail)
    EnvelopesReference components for space claims and selections
    Assembly VisualizationSorts components by rebuild time, triangles, mass, any property
    Performance EvaluationReports slow mates, in-context references, circular references, heavy graphics

    Habits that help

    • Mate to planes and origins of parts; fewer, simpler mates; fix what does not move.
    • Cosmetic threads, not modelled threads; simplified configurations of purchased parts.
    • Sub-assemblies that match how the product is built; keep them rigid unless motion is needed.
    • Keep files on a fast local disk or a properly configured PDM cache, not a slow network share.

    Do it in SolidWorks

    1. Open the reducer assembly with Mode: Large Design Review from the Open dialog; time it. Measure the shaft centre distance.
    2. Reopen as Lightweight; add a mate — note the parts resolving.
    3. Assembly ▸ Assembly Visualization: add a column SW-Rebuild Time; sort; identify the heaviest part.
    4. Evaluate ▸ Performance Evaluation: read the mate and rebuild reports.
    5. In the input-shaft sub-assembly: ConfigurationManager ▸ right-click ▸ Add SpeedPak, keep the shaft ends and bearing outer faces.
    6. Tools ▸ Defeature on the whole reducer: keep outer faces and mounting holes; save as a part to send to a customer.

    • One in-context reference chain can slow a whole assembly — lock or break them after release (Day 19).
