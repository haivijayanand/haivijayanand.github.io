PDM: Vaults, Versions, Workflows and Revisions

Many people, one truth. PDM keeps files in a vault with check-in/out, versions, workflows and revisions — the end of "final_v7_REALLY_final.SLDPRT".

⏱ about 2–3 hours🧪 Lab: Workflow simulator❓ 5-question quiz

1Today's goals

  • Explain vault, local cache, check-out and check-in
  • Tell versions from revisions
  • Follow a release workflow with approvals
  • Use where-used and rollback

2Vault thinking

SOLIDWORKS PDM stores files in a vault on a server; you work in a local cache (a vault view in Windows Explorer). PDM Standard comes with SOLIDWORKS Professional/Premium; PDM Professional adds scale, replication, a web client and more automation.

ConceptMeaning
Check outGet write access; others see who has it
Check inSend changes to the vault → new version (1, 2, 3…)
WorkflowStates (Work in Progress → Pending Approval → Released) and transitions with permissions
RevisionA label (A, B, C…) given on release; written into the title block and revision table
Data cardForm showing file properties; edits write to custom properties
Where Used / ContainsWhich assemblies use this part; what this assembly references
Get version / RollbackOpen or restore an older version

Without PDM, use at least a clear folder structure, Pack and Go for releases and a written revision rule. On the 3DEXPERIENCE platform, the same ideas are called maturity states and revisions.

3Do it in SolidWorks PDM

  1. Log in to the vault view in Windows Explorer; browse to your project folder.
  2. Drag a new part into the vault. Fill the data card (Description, PartNo, Material) and check it in.
  3. Open it in SolidWorks, change a dimension; the PDM task pane shows it is not checked out — check out from there.
  4. Save and check in with a comment. Look at the History tab: version 2.
  5. Change state: Submit for approval. As the approver, Approve → revision A.
  6. Right-click ▸ Where Used to see the assemblies affected by a change.
  7. Make a change request, edit, and release revision B. Compare A and B with Get ▸ version.

4Lab: workflow simulator

Try the buttons in different orders. The simulator refuses illegal moves just as a PDM workflow would — editing without check-out, submitting a checked-out file, approving nothing.

5Pro tips and common mistakes

  • Check in at the end of every day; a checked-out file on a laptop is invisible to everyone else.
  • Check in assemblies with their parts so references stay consistent.
  • Rename and move files inside the vault (or with SolidWorks Rename) — Windows rename breaks references.
  • Agree the revision scheme before the first release: letters, numbers, prototype stages (P1, P2) then A.

6Practice

Write your team's revision rule on one page: when the version changes, when the revision changes, letters to skip, who approves, and what goes in the revision table. Use the simulator to walk through one full change.
