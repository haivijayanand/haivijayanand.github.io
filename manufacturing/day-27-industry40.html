30-Day Manufacturing Course · Week 5 · Day 27

Data, MES and Industry 4.0

From clipboards to connected machines: the automation pyramid, ERP and MES, collecting machine data automatically, dashboards that drive action, traceability, and a practical path into Industry 4.0 for a medium-sized plant.

⏱ about 2–3 hours🧪 Lab: Live machine data❓ 5-question quiz

1Today's goals

  • Describe the automation pyramid from sensors to ERP
  • Know what MES does that ERP does not
  • Plan automatic machine data collection: states, counts, speeds and stop reasons
  • Design a dashboard that leads to action
  • Take small, paid-back steps into IIoT, analytics and digital twins

2The automation pyramid

LevelSystemsTime scale
4 EnterpriseERP — orders, purchase, inventory, financeDays, months
3 OperationsMES — schedules, job tracking, OEE, quality records, traceability, labourShifts, hours
2 SupervisorySCADA, HMI, historiansMinutes, seconds
1 ControlPLCs, drives, controllersMilliseconds
0 FieldSensors, actuators, gauges, encodersMicroseconds

Industry 4.0 connects these levels (OPC UA, MQTT) so that data flows up for decisions and instructions flow down, and adds cloud analytics, condition monitoring, digital twins and, increasingly, AI assistants that read the data and draft reports.

3What to collect

Machine stateRunning, stopped, changeover, idle (no order), fault — from PLC signals or a simple current sensor.
Counts and speedsMetres, pieces, kg; actual vs rated speed.
Stop reasonsOperator picks from a short list on a tablet when a stop exceeds 2 minutes.
Process valuesTemperatures, tensions, viscosities, coat weights, register error — with timestamps and job number.
Quality resultsLab tests tied to roll IDs.
GenealogyWhich input rolls and lots went into which output — the traceability tree.
Data quality first. A dashboard built on hand-typed, end-of-shift numbers is a nicer-looking clipboard. Automatic state and count capture plus disciplined stop-reason entry gives OEE you can trust (Day 3).

4Digital in a converting plant

Roll IDs, recipes and live OEEEvery roll gets a barcode or QR label at birth (extruded, printed, laminated, slit), linking job, machine, operator, time, input rolls and test results — so a complaint traces back to the exact film lot and adhesive batch in minutes. Recipes for each job (speeds, temperatures, tensions, slitter knife positions, pouch dimensions) are stored and loaded at changeover (Day 11). Online thickness gauges, 100 % print inspection cameras and register controllers feed defect maps that travel with the roll so the slitter or pouch machine can cut defects out. A live OEE screen at each machine and a plant board in the office replace the morning argument about what happened last night. Many converters start with low-cost sensors and an open-source or SaaS dashboard before buying a full MES.

5Worked example

Payback of automatic stop logging8 machines; manual logs captured only stops > 15 min. Sensors + tablets + dashboard ≈ ₹12 lakh. First month of real data: 2.1 h/day/machine of short stops (2–15 min) never recorded before. Top cause on presses: waiting for ink approval (28 %); on pouch machines: film splice (22 %). Fixing these two recovered 0.6 h/day/machine × 8 × 330 days × ₹4 000 contribution/h ≈ ₹63 lakh/yr.

6A practical digital roadmap

  1. Start with a business problem (OEE, traceability, energy) — not with a technology.
  2. Capture machine states and counts automatically on the bottleneck; add stop reasons.
  3. Show it live at the machine and review daily; act on the top losses.
  4. Add roll / batch IDs and genealogy; link lab results.
  5. Connect to ERP for orders and stock; add recipes and condition monitoring.
  6. Only then add analytics, prediction and AI — on data you trust. Secure every connection (cybersecurity) and back up.

7Lab: live machine data

A simulated pouch machine sends its speed every second. Press P to run the shift. Stops are classified automatically; OEE and the stop Pareto build up live — the view an MES gives a supervisor.

8Pro tips and common mistakes

  • Fewer screens, more action. Every number on a dashboard should have an owner and a reaction.
  • Do not let IT and production build separate systems — agree one data model (machine, job, roll, reason codes).
  • Old machines can be connected with a current sensor and an encoder; you need not replace them.
  • Managers: insist on the problem and the payback before the software demo.

9Practice

  2. Design a one-screen dashboard for your bottleneck: what six numbers would you show?
  3. Estimate the payback of automatic stop logging on that machine.
