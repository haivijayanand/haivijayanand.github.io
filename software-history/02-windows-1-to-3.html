EPISODE 02 · 1985 – 2001

Windows 1.0 to 3.11: the graphical layer on DOS

Windows began not as an operating system but as a program you started from the DOS prompt. Over eight years it grew from tiled windows that few people used into Windows 3.x, the interface that put a mouse on almost every office desk.

01The requirement: computers for people who would not learn commands

By 1983 the IBM PC had conquered offices, but using it meant memorising commands such as COPY A:*.WK1 C:\LOTUS. Meanwhile Xerox PARC had shown a different idea: the Alto (1973) and the commercial Xerox Star (1981) with windows, icons, a mouse and "what you see is what you get" documents. Apple turned that into the Lisa (1983) and the Macintosh (January 1984). On the PC side, VisiCorp shipped VisiOn in late 1983.

Microsoft, which also wrote applications for the Mac, announced "Interface Manager" — renamed Windows — in November 1983. Its brief was shaped by the installed base of DOS PCs:

RequirementWhyHow Windows answered it
Run on existing PCsMillions of 8088 machines with 256–640 KB and floppy disksRan as a program on top of MS-DOS; no new hardware or OS needed
Keep running DOS programsLotus 1-2-3 and WordPerfect users would not give them upDOS applications launched from Windows, later in their own windows (386 mode)
One look for all applicationsEvery DOS program had its own keys and menusShared menus, dialog boxes, scroll bars and later IBM's CUA keyboard rules
Device independenceEach DOS program shipped its own printer and screen driversGDI (Graphics Device Interface): applications draw once, Windows drivers render on any screen or printer

03See it: cooperative multitasking

In Windows 3.x the operating system did not take the CPU away from a program; each program had to hand it back. One misbehaving program froze everything — the famous hourglass. Press Run, then make one program misbehave.

Each bar counts the time slices a program has received.

Windows 95 (for 32-bit programs) and Windows NT replaced this with pre-emptive multitasking: a hardware timer lets the operating system interrupt any program. Episode 06 and Episode 08 cover that change.

04Version explorer

Blue chips: Windows 1.x and 2.x. Amber chips: the 3.x family that succeeded.

Why 3.0 succeeded when 1.0 and 2.0 did not: the hardware caught up. The 386 and VGA displays let Windows use megabytes of memory and 16 colours, and Microsoft's own Excel and Word for Windows gave people a reason to switch.

05Apple v. Microsoft

In 1985 Microsoft signed an agreement with Apple licensing some Macintosh visual elements for Windows 1.0. When Windows 2.0 added overlapping windows, Apple sued in March 1988, claiming the "look and feel" of the Mac. The courts found that most of the disputed elements were covered by the 1985 licence or were not protectable ideas; Apple lost at trial and on appeal (1994), and the US Supreme Court declined to hear the case in 1995. Xerox's own suit against Apple was also dismissed. The result: graphical interface ideas became common property of the industry.

08Decline and retirement

  • August 1995: Windows 95 merged DOS and Windows into one product with the Start button, long file names and 32-bit programs. Windows 3.x sales collapsed within two years.
  • 31 December 2001: Microsoft ended support for Windows 1.0, 2.x and 3.x together with MS-DOS.
  • November 2008: Microsoft stopped licensing Windows 3.11 to makers of embedded systems — some cash registers and industrial controllers were still shipping with it.
  • Long tail: 16-bit Windows programs ran on 32-bit Windows NT through Windows 10 using the "WOW" layer; 64-bit Windows cannot run them.

10Legacy

  • The message loop and window procedure of 1985 are still the core of every Win32 program today.
  • Ctrl+X / C / V, menus with underlined access keys, Alt+Tab and dialog box conventions became universal.
  • TrueType fonts (3.1) and device-independent printing ended the era of per-application printer drivers.
  • DLLs brought code sharing — and "DLL hell" when programs overwrote each other's versions.

11Lessons for engineers

  1. Launch on the installed base. Running on top of DOS meant no one had to throw anything away.
  2. Version 3 is often the real version 1. The idea was right in 1985; the hardware arrived in 1990.
  3. Platforms win through their own killer applications. Excel and Word gave Windows reasons to exist.
  4. Trusting every program to behave does not scale. Cooperative multitasking worked until one program misbehaved.
