Editors and developer tools: Notepad++ and beyond

Windows Notepad could open a text file — and little else. Engineers, programmers and system administrators needed tabs, syntax colouring, search across files, huge log files and the right line endings. Open-source editors and tools filled the gap: Notepad++, Vim, VS Code's open core, Git, PuTTY, WinSCP and FileZilla. In 2025 Notepad++ also became a case study in how even a text editor's updater can be attacked.

01The requirement: more than Notepad

Windows Notepad (with Windows since 1985) was deliberately tiny. For decades it could not handle Unix line endings (fixed in 2018), opened large files slowly, and had no tabs (added in 2023). Engineers work with exactly the files Notepad handled badly: configuration files, scripts, CSV exports, data-acquisition logs, G-code, XML and JSON.

02Notepad++

Don Ho wrote Notepad++ in C++ for his own use and released it on SourceForge in November 2003 under the GPL. It is built on Scintilla, Neil Hodgson's open-source editing component, and uses the plain Win32 interface, so it starts instantly and runs on old PCs. A plugin system (Compare, NppFTP, JSON Viewer, XML Tools and hundreds more) let users add what they needed. It became one of the most-used editors among programmers on Windows, regularly near the top of developer surveys in the 2010s. Don Ho is known for naming releases after political causes, which has brought both support and boycotts.

The 2025 updater hijack

Notepad++ checks for updates with a small helper program, WinGUp, which downloads a short XML file naming the latest installer. Until version 8.8.9, WinGUp did not strictly verify the installer's digital signature. Attackers compromised the project's shared hosting provider and, from about June 2025 until early December 2025, redirected update requests from carefully chosen targets to malicious servers that delivered a backdoored installer. Users who downloaded installers directly from the official website were not affected.

  • Version 8.8.9 (9 December 2025) made signature and certificate checks mandatory; the website moved to a provider with stronger security.
  • The issue was tracked as CVE-2025-15556 and attributed by researchers to a China-linked group.
  • The project advised installing 8.9.1 or later manually so that the hardened updater replaced the old one; 8.9.2 fixed a further search-path flaw.
Lesson: an update mechanism is part of the product's security. Signed installers, verified downloads and secure hosting matter as much as the code itself — true for an engineering data tool as much as for a text editor.

04See it: line endings and encodings, byte by byte

The same text can be stored in different bytes. Windows ends lines with CR LF (0D 0A), Linux and macOS with LF (0A) — a legacy of teleprinters and of CP/M and MS-DOS (Episode 01). Encodings decide how letters such as "°" or Tamil characters become bytes. Mismatches are why a script fails on Linux with ^M errors, or a CSV shows "Â°C".

09Lessons for engineers

  1. Small, fast tools get used. Notepad++ won by starting instantly and doing the common jobs well.
  2. Reuse a good component. Scintilla powers many editors; nobody had to write syntax colouring from scratch.
  3. Learn regular expressions. One pattern can clean a thousand lines of test data.
  4. Secure the update path. Verify signatures; prefer package managers and official sites.
